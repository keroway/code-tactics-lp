## Why this matters

`pnpm-workspace.yaml` pins transitive dependency `fast-uri` to `>=3.1.5 <4`,
but four high-severity advisories (host confusion / SSRF) were published after
that floor was set, all patched in `>=3.1.6`. The lockfile currently resolves
`fast-uri@3.1.5`, so `pnpm audit --audit-level=high` reports 4 high findings
(and the weekly osv-scan workflow has the same exposure). Raising the floor to
`>=3.1.6` closes the bites and removes the high-severity audit noise on a
dependency that is only reachable via the typecheck tool chain
(`ajv > yaml-language-server > @astrojs/language-server > @astrojs/check`).

## Steps

### Step 1: Bump the override floor

In `pnpm-workspace.yaml`, change exactly one line and extend the attached
comment so the reason stays self-documenting (this file's convention is a
Japanese comment naming the advisory IDs and the dependency path):

```yaml
# osv-scanner 検出分（2026-08-09、#139）。
# GHSA-7p8r-x3mc-p8w7 (fast-uri <3.1.5) — backslash authority introducer による host confusion。
#   ajv > yaml-language-server > @astrojs/language-server > @astrojs/check 経由（型チェック時のみ）。
# 2026-09-03: 新規 High advisory 4 件 (IDN canonicalization / IPv6 normalization /
#   percent-decoding SSRF / percent-encoded scheme。vuln <3.1.6、patched >=3.1.6) に
#   対応し下限を引き上げ。
fast-uri: ">=3.1.6 <4"
```

**Verify**: `rg 'fast-uri: ">=3.1.6 <4"' pnpm-workspace.yaml` → one match on the
`fast-uri` line.

### Step 2: Regenerate the lockfile

Run `pnpm install`. The resolver must pick a 3.x version `>=3.1.6`
(workspace policy pins `minimumReleaseAge: 4320` minutes / 3 days; fast-uri
3.1.6 is old enough to satisfy it, but if resolve fails here it is a STOP
condition).

**Verify**:

- `pnpm install` → exit 0
- `rg 'fast-uri@3\.1\.([6-9]|1[0-9])\b' pnpm-lock.yaml` → at least one match
  (i.e. resolved version is 3.1.6 or newer within the 3.x line)
- `rg 'fast-uri@3\.1\.[0-5]\b' pnpm-lock.yaml` → no matches

### Step 3: Re-run the quality gate and audit

**Verify**:

- `pnpm run check` → exit 0
- `pnpm audit --audit-level=high` → run it; the output may still exit nonzero
  because of `extract-zip`, but `fast-uri` must no longer appear among the
  high findings:
  `pnpm audit --audit-level=high --json 2>/dev/null | jq -r '.advisories[] | .module_name' | sort -u`
  → lists `extract-zip` and possibly `qs` (moderate), but **not** `fast-uri`.
